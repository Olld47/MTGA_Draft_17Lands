===================== RELEASE NOTES 1.0.2 =====================
### Highlights

#### 官网安全加固

数据渲染全面加固：所有第三方数据（GitHub releases / ETL 数据集 / 赛事日历）的 HTML 插值统一经 `escapeHtml` 转义，release notes 渲染改为 DOMParser 白名单净化（仅保留 markdown 生成的标签与 class，事件处理器 / style / 非 http(s)/mailto 链接全部剥离）；纯消息渲染全部改为 DOM 构建（textContent），站点不再用 innerHTML 承载任何非受控文本。i18n 字典抽离为 `i18n-messages.json`（部署期注入脚本），测试直读 JSON 做键覆盖守卫。

#### 发布流程修复

pre-release / release 工作流适配 GitHub "immutable releases" 设置：release 一经发布即冻结、无法再上传资产——改为先建草稿（draft）上传资产，再发布草稿（触发 `release.published`），修复了 pre-release 上传 .msi/.dmg 失败的问题。同时升级全部 9 个 workflow 的 5 个 action 至最新版并锁定完整版本号（checkout v7.0.1 / setup-node v7.0.0 / upload-artifact v7.0.1 / download-artifact v8.0.1 / setup-uv v10.0.1），修复 `setup-uv@v10` 无法解析（v8 起不再发布 major 短标签）与 download-artifact 误挂 `if-no-files-found`（仅 upload-artifact 合法）两处流水线报错。

<details>
<summary><b>English</b></summary>

#### Security hardening on the website

All third-party data (GitHub releases, ETL datasets, event calendar) is now HTML-escaped at the interpolation boundary, release-note rendering uses a DOMParser allowlist sanitizer (only markdown-generated tags/classes survive; event handlers, style attributes and non-http(s)/mailto links are stripped), and plain message rendering is DOM-built (textContent) — no innerHTML ever carries uncontrolled text. The i18n dictionary moved to i18n-messages.json (embedded at deploy time), with tests reading the JSON directly for key-coverage guards.

#### Release pipeline fix

The pre-release / release workflows now match GitHub's "immutable releases" setting: a release freezes the moment it is published, so assets must be uploaded while it is a draft. The workflows create a draft, upload assets, then publish it (firing release.published) — fixing the failed .msi/.dmg asset uploads on pre-releases. All nine workflows also pin the latest full release tags for five actions (checkout v7.0.1 / setup-node v7.0.0 / upload-artifact v7.0.1 / download-artifact v8.0.1 / setup-uv v10.0.1), fixing two pipeline errors: `setup-uv@v10` could not resolve (short major tags stopped being published after v8) and `if-no-files-found` was wrongly passed to download-artifact (valid only for upload-artifact).

</details>
